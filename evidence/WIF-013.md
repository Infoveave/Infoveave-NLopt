# WIF-013 — Package and release pipeline evidence

## Package boundary

`Infoveave.NLopt` `2.11.0` packs the managed assembly, XML documentation, source/symbol metadata, package README, managed-package notices, and `buildTransitive/Infoveave.NLopt.targets`. Its managed version matches the pinned NLopt native version. Package verification rejects native files, runtime folders, missing documentation/targets, download behavior, an incorrect license declaration, and packages over 5 MiB.

The `buildTransitive` target requires a caller-supplied extracted bundle for executable and test builds, copies it to `nlopt/` for build and publish output, leaves class-library builds independent of native assets, and offers an explicit compile-only skip. It performs no network operation.

## Local clean-consumer result

The consumer suite packs the project, copies consumers outside the source tree, uses a fresh NuGet cache and the packed file as its only source, then verifies:

- class-library restore/build without native assets;
- actionable executable failure when assets are absent;
- intentional compile-only build followed by runtime failure with no system fallback;
- wrong-RID build failure;
- direct restore/build/run and bounded solve;
- publish output containing the complete `nlopt/` directory;
- a real intermediate NuGet package providing `Infoveave.NLopt` transitively;
- native-file corruption rejected by the managed loader.

Package content, release-tag, Windows-script policy, workflow policy/YAML, explicit acquisition, and runtime archive tests also pass locally.

## Workflows and hosted qualification

CI and publish workflows use fixed runner generations, .NET 10, Python 3.13, and CMake 4.4.3. They build and run each native RID on its actual platform. Tag publication requires `v<ManagedPackageVersion>`, pushes the managed package only to the Infoveave GitHub Packages feed, and attaches immutable RID ZIP/checksum/notices assets to the matching GitHub release. Manual publish workflow runs qualify artifacts without publishing them.

Build and qualification jobs receive only read access and do not persist checkout credentials. Only the final tag-gated publish job receives scoped `contents: write` and `packages: write` access. Publication is retry-safe: an existing release asset or NuGet version is downloaded and compared byte-for-byte, identical content is retained, and different content is rejected without replacement. Mocked tests cover initial publication, an identical retry, and rejection of changed bytes. Stable tag `v2.11.0` is authorized only after all platform jobs in the same workflow pass.

The remote CI matrix passed on every supported platform, and stable tag `v2.11.0` published `Infoveave.NLopt` `2.11.0` to the Infoveave GitHub Packages feed plus the three native runtime bundles to GitHub Releases.
